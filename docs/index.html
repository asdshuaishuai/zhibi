Product law

铁律不是「AI 不能写正文」，
而是「AI 的一切产出都只是提案」

包括整章草稿。作者采纳之前不落盘，采纳时自动留快照可回滚。完成与否以磁盘为准，不信模型口头声明。

AI 可以

全部以提案形式交付，进收件箱等你处理
  • 构建核心大纲与事件时间线（作者真相 / 读者已知双栏）
  • 盘点伏笔、登记埋点（F 编号、五档节奏、种下原文）
  • 搭章节骨架：场景层节拍 + 章尾钩子 + 硬交付 + 伏笔触点合同
  • 规划卷级弧光（20–40 章路标 + 伏笔收支表 + 期待感账）
  • 写整章草稿、按你的意见修订草稿
  • 提取记忆、一键召回上下文包与写作备忘
  • 一键验证、全书连贯性审查（只查客观错误，只报告不代改）
  • 埋点修复方案、大纲同步建议、去AI味逐处建议

AI 永远不可以

这些不是提示词约定，是代码里没有那条路径
  • 提案未经作者采纳就改任何台账、大纲或正文
  • 替作者做正典决定（角色生死、世界规则、伏笔取舍）
  • 在作者拒绝后保留数据
  • 改正文而不留快照
  • 声称「已完成 / 已保存 / 已采纳」——一切以落盘为准
  • 用「风格好不好」的主观评价代替作者判断（审校只查客观错误）
两个例外的边界也写死了：骨架闸门允许模型在同一轮里拿确定性检查结果自我修正，一键成章允许 草稿 → 审查 → 去AI味 自动串到底——但两者都停在「采纳」之前，骨架更不会被自动批准： 它是写前契约，属于正典决定，必须你亲自点头。
Capabilities

把网文这门手艺，做成可执行的账

创作法典不是往提示词里塞一段鸡汤，而是沉淀成代码能消费的知识与确定性检查——同一套法典既指导生成，也用来验收生成结果。

创作法典

13 个流派档案（读者预期 / 题材禁区 / 可用爽点形态 / 开篇律 / 节奏参数 / 体系通胀控制）＋ 网文创作法（黄金三章、期待感管理、打脸循环、金手指代价律、卷弧、主角能动性）＋ 传统文学创作法（草蛇灰线、白描、意象、留白、视角距离、典型人物、春秋笔法、起承转合、文气、复调）。按能力裁剪后注入，不整本塞。

13 流派 · 7 种钩子形态

卷骨架 · 章骨架

先规划 20–40 章的卷级弧光（起承转合 + 章级路标 + 伏笔收支表 + 期待感账），认可后再逐章细化成节拍。每拍带场景层：视角贴着谁、地点、时间标记、在场人物、这一拍的转折。

写前契约

骨架闸门

批准之前用确定性代码给骨架打分（0–100）：到期伏笔有没有进合同、章尾钩子是否挂在具体物件上、连续几章是否同一种钩子（套版感）、视角有没有漂移、同一时间有没有人分身两地、字数预算合不合理。不合格直接回灌模型当轮自纠。

11 组检查 · 零 LLM 成本

全书连贯性审查 ＋ 埋点修复

死者复出、位置跳跃、人称漂移、时间线倒挂、伏笔台账烂账（种下原文对不上正文、兑现逾期、疑似已收未记账、动作日志指向不存在的章）。每条烂账都配一个可一键采纳的修复动作：补埋 / 改期 / 回收 / 搁置 / 放弃 / 校正原文 / 补登记。

20 类检查 · 只改台账不动正文

大纲实时对账

大纲不该是建书时生成一次、之后越来越不可信的旧计划书。它把「计划」与「正文里实际发生的」逐事件对账：已发生 / 疑似偏移 / 未发生 / 已取消，再算剧情线健康度（健康 / 放缓 / 停滞 / 断线 / 待收束）与阶段完成度，产出更新提案。采纳后大纲才是活文档。

计划 vs 实际

去AI味

25 项确定性检测（零成本、随打字更新）分三层：措辞层禁用词与「不是A而是B」、心理层认知动词堆叠与抽象名词密度、结构层段落等长 / 句长平坦 / 段首同构 / 对白占比 / 信息倾倒 / 转场缺失 / 万能过渡；再加网文命门（章末钩子空泛、情绪曲线平坦）。还有反向保护：把句子全打碎本身就是一种新指纹，同样报警。

25 检测器 · 三 pass · 逐条采纳

一键成章 · 分段写作

⌘⇧W 真一键：草稿 → 一致性审查 → 去AI味 自动串到底，产出全进收件箱，停在采纳之前。3000 字以上的长章按骨架节拍切块，每块带着上一块实际写出来的结尾续写，非末块被明确要求「不要收束本章」，最后拼成一份草稿提案。

⌘⇧W · 600–2400 字/段

交叉记忆中枢

双时态事实三元组（谁在从第几章起相信什么、什么时候失效）＋ 人物别名表，派生出人物关系图 / 剧情图 / 事件图三张可拖拽的图。写到 100 章不会忘第 3 章的钩子；「一键召回」按当前章造上下文包。

双时态 · 图谱

稿纸主权

专注模式（⌘⇧F）全窗只剩稿纸；正文是权威纯 markdown，随时可以整个带走；删除即废纸篓可恢复；导出合并稿 / oh-story 目录回写 / 分卷 TXT；API Key 存 macOS 钥匙串，不落盘、不进仓库。

本地优先
Why this one

三条路都被试过，然后才有了执笔

下面三种方案，是长篇作者真实会走的岔路。它们各自都能撑几十章，撑不到第三百章。

对比 · 开个聊天窗口让 AI 写

模型的记性，撑不起你的体量

聊天框的上下文是金鱼的：写到第三百章，它已经不记得第 8 章那把刀，也敢让断了手臂的角色重新举剑。执笔把「谁在什么时候知道什么、哪条伏笔种在哪、承诺几章内兑现」全部记成本地可校验的账，喂给模型的是造好的上下文包，不是它的回忆。

对比 · 大纲与世界观管理工具

管计划容易，对账难

传统写作工具存的是你打算写什么。可真正的痛苦来自「我实际写了什么」和那份计划已经分叉了。执笔逐事件把两者对账：已发生 / 疑似偏移 / 未发生 / 已取消，再算每条剧情线的健康度（健康 / 放缓 / 停滞 / 断线 / 待收束）——大纲于是变成活文档，而不是越来越不敢打开的旧计划书。

对比 · 只做措辞替换的去AI味插件

换词救不了结构病

把「一丝」换成「些许」不叫去AI味。执笔 25 项检测里有一半在管结构：对白占比是否掉进说明文腔、连续九百字有没有信息倾倒、章末钩子是否挂在具体物件上、情绪曲线是不是全章一个速度。还带反向保护——把句子全打碎本身就是一种新的机器指纹，同样报警。

Verification

不打开界面也能证明它没坏

项目自带一个无头自检 CLI 和一个 mock 模型端点。前者跑纯函数与内存账本，后者把「宿主交工具面 → 模型回调工具 → 落成提案 → 采纳 → 落盘」整条链变成可重复回归——不需要 API Key。

Who it's for

说清楚它适合谁，也说不适合谁

与其让你装完再失望，不如现在就说。

✓如果你是这样，它帮得上

体量一上来，账就先崩
  • 写长篇网文 / 类型小说，一次开两三本，靠记忆已经管不住伏笔
  • 被「设定矛盾」「角色在两地同时出现」「这条线写着写着断了」折磨过
  • 想让人机协作，但拒绝让 AI 替你落笔——正文必须是你自己的
  • 稿子只肯放本地，不接受「上传到我们的云端帮你管理」
  • 已经在用 oh-story / InkOS 这类社区工作流，想要一个能读能写回的工具

✕如果你要这些，别浪费时间

不是做不出来，是刻意不做
  • 想要「一键生成一整本书」——这个功能不存在，而且是产品铁律明确禁止的
  • 只想要一个更漂亮的纯文本编辑器，不需要台账、对账、审查
  • 要 Windows 或 Linux ——目前只有 macOS 14+，没有跨平台计划
  • 完全离线、一个 API 端点都不想配 —— 理账可以离线，AI 提案不行
  • 期待开箱即用的商业级打磨 —— 它是作者自己在用的工具，界面还会改
Under the hood

技术取向

界面SwiftUI（macOS 14+），原生 AppKit 混排：稿纸用 NSTextView 保住中文输入与富文本渲染，Markdown 只读预览走 TextKit 1 以支持表格
Agent 基座按 fx / libfx 的模型在 Swift 内同构实现（会话、流式事件、checkpoint 由宿主持久化）；传输走 OpenAI 兼容 SSE + tool-calling，DeepSeek / GLM / Kimi / MiniMax / Ollama 换 baseURL 即换
确定性引擎验证、连贯性审查、大纲对账、骨架闸门、去AI味扫描、记忆图谱——全部零 LLM 成本，随时可跑、结果可复现、可被自检钉死
存储一个 .zhibi 目录就是全部：正文是权威 markdown，结构是 JSON，原子落盘、快照可回滚、无数据库、无云端
凭据API Key 存 macOS 钥匙串，不写进配置文件、不进仓库、不进日志
工程project.yml + xcodegen 生成 Xcode 工程；SwiftPM 依赖；Debug / Release 与 CLI 三套 target 全部 CI 可无头构建
Get it

怎么跑起来

目前从源码构建，还没有签名好的安装包。

# 1. 生成 Xcode 工程
brew install xcodegen
xcodegen generate

# 2. 构建 App（执笔.app）
xcodebuild -scheme ZhiBi -configuration Release \
  -skipMacroValidation build

# 3. 无头自检（不打开 GUI、不碰真实数据）
xcodebuild -scheme ZhiBiCli -configuration Debug \
  -skipMacroValidation build
ZhiBiCli                    # → 280 项全通过

# 4. 不需要 Key 也验一次整条 agent 链路
python3 Scripts/mock_model_server.py 8799 /tmp/zbdump &
ZhiBiCli --mock-agent http://127.0.0.1:8799/v1 /tmp/zbdump
                            # → 94 项

构建产物在 DerivedData/.../Release/执笔.app， 直接 open 就能用。 首次使用在「设置」里填一个 OpenAI 兼容端点的 API Key（存钥匙串），或者用 Ollama 完全本地跑。

它现在是什么阶段：一个作者自己在用的工具，不是打磨过的商业产品。 界面会改，数据格式保证向后兼容——自检里有一整节专门守这条，因为丢稿子是不可原谅的。
